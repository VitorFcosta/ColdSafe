# CS-20 — Implementar repositório InfluxDB

- **Status:** Concluída
- **Dependências:** Testar escrita e consultas no InfluxDB; Configurar volume persistente do InfluxDB
- **Frente / prioridade:** Dados / P0

## Aceite

Leituras válidas são persistidas e consultadas por dispositivo.

## Entrega

- Criado o pacote `backend.app.repositories` com um adaptador `InfluxReadingRepository` para persistir leituras validadas no measurement `environment_reading`.
- Criado `StoredReading`, objeto imutável para leituras reconstruídas a partir do InfluxDB.
- Criada a fábrica `create_influx_repository`, com `InfluxSettings` validado, token oculto em representações, rejeição de credenciais, query string e fragmento na URL, e escrita síncrona via `SYNCHRONOUS`.
- Adicionada a dependência `influxdb-client==1.50.0` em `backend/requirements.txt` e no lock de desenvolvimento.
- Criada a evidência TDD local em `docs/testing/influxdb-repository.tdd.md`.

## Garantias

- Escrita grava `device_id` e `status` como tags, `schema_version`, `temperature_c` e `humidity_percent` como fields, e `received_at` como timestamp UTC.
- Consultas usam bind parameters do Flux via `params`, sem interpolar `device_id` na string da query.
- `get_latest(device_id)` retorna a última leitura ou `None` quando não há dados.
- `list_history(device_id, start, end, limit)` valida timezone, intervalo e limite `1..1000`, trazendo as últimas leituras em ordem cronológica para exibição.
- O ciclo de vida fecha `write_api` antes do cliente InfluxDB e fecha o cliente mesmo se o flush do write API falhar.
