# B2-08 — Proxy do frontend, portas e bootstrap seguro

- **Status:** Concluída
- **Dependências:** [B2-06](B2-06.md), [B2-07](B2-07.md)
- **Frente / prioridade:** Infraestrutura / P0
- **Meta original:** 2026-10-18

## Aceite

Aplicação funciona pela porta frontend; serviços internos não publicados e dados existentes preservados.

## Passo a passo

1. Servir build Vue por servidor estático/proxy, encaminhando REST, documentação e WebSocket ao FastAPI.
2. Retirar publicação normal de API/MQTT; interfaces administrativas opcionais só em 127.0.0.1, com links na aplicação.
3. Gerar segredos por script fora do Git, sem sobrescrever existentes; usar containers de aplicação sem root e inicialização idempotente.

## Áreas e interfaces afetadas

Compose, configuração do proxy, script de segredos e frontend.

## Como testar

REST, /docs e WebSocket via proxy; segunda inicialização não troca credenciais nem apaga dados.

## Resultado — 14/10/2026

Registro da entrega inicial; a correção posterior da inicialização na pasta real
do usuário está ao final deste cartão. Evidências e limites abaixo descrevem
aquele ensaio, não substituem a verificação posterior.

Aceite cumprido para a base v1/v2 atual com RabbitMQ da B2-07 presente.
Execução iniciada em 13/10 e concluída na retomada de 14/10, sem consultar Notion
nem replanejar o roadmap. Contratos/serviços de negócio AIoT v3 continuam futuros.

### Erros encontrados e como testar as correções

1. **Build sem permissão:** `node` não possuía `/app` e Vite não criava `dist`.
   Arquivo: `frontend/Dockerfile`. Solução: `chown node:node /app` antes de
   trocar de usuário; executar o build sem root. Build e integração final passaram.
2. **Fixture v1 inadequada para WS:** `runtime.after_save` publica `reading`
   apenas para v2; v1 continua no histórico. Arquivo corrigido: teste de integração.
   Usar v2 com `light_percent` e tópico v2; não modificar runtime legado para
   satisfazer uma suposição errada do teste. Integração final recebeu o evento.
3. **JWT mudava no teste de reinício:** fixture global do pytest fornece chave
   aleatória por caso e Compose prioriza ambiente sobre `.env`. Arquivo: helper
   do teste de integração. Solução: remover variáveis do exemplo do ambiente dos
   subprocessos Compose, deixando o `.env` descartável ser a fonte. Hash da chave
   efetiva, JWT anterior, login e dados passaram após a segunda subida.
4. **Expectativas estáticas antigas:** testes esperavam Vite, API/MQTT publicados
   e rede de borda no backend. Atualizados para o contrato B2-08; rede YAML vazia
   normalizada para map vazio no teste. Regressão final passou.

## Correção posterior — inicialização na pasta Documents, 14/10/2026

**Resultado:** removida a dependência de montagens de arquivos do host nos
brokers e nos dois inicializadores. O aceite permanece concluído para a base
atual. Esta execução também iniciou o ambiente pessoal pelo Compose, com seu
`.env` e volumes existentes; a restrição do ensaio inicial acima é histórica.

### Causa observada e solução

O log do usuário mostrou `install: read error: Resource deadlock would occur`
no `mosquitto-init`. A inspeção do RabbitMQ mostrou `edeadlk` ao abrir
`/etc/rabbitmq/rabbitmq.conf`. Os dois erros ocorreram na leitura de arquivos
montados da pasta do projeto. Isso comprova falha de leitura pelo compartilhamento
Docker/host; não identifica com certeza um provedor de sincronização como causa.
Não havia evidência de senha incorreta nesses erros.

O teste inicial copiava fontes para fora de Documents e deixou de reproduzir essa
condição. Corrigidos tanto o runtime quanto essa lacuna de validação: configuração,
ACL e bootstrap entram nas imagens via `COPY`; os testes constroem diretamente
da pasta real do projeto. Credenciais geradas, definições privadas e dados
continuam nos mesmos volumes nomeados.
